### 2.2 数据流（完整生命周期）

```
╔═══════════════════════════════════════════════════════════════╗
║  Phase 1: 脚本加载 (index.html L538-542, 严格顺序)            ║
╚═══════════════════════════════════════════════════════════════╝

1) <script src="scripts/dataBundle.js">
   → window._CROSSING_DATA = { "data/world_registry.json": {...}, ... }
   → 包含所有 data/ JSON 内嵌为 JS 变量

2) <script src="scripts/dataService.js">
   → 定义 loadJSON / saveJSON 等全局函数
   → 不执行任何初始化，仅注册 API

3) <script src="scripts/app.js">
   → 声明全局变量: characters = {}, currentCharName = null, dmMode = false
   → 注册 DOMContentLoaded 回调

4) <script src="scripts/character.js">
   → 定义 SKILL_CATEGORIES, ABILITY_IDS 等常量
   → 声明模块变量: _pageInited, _talents, _enhances, _badges 等
   → 注册所有角色面板构建函数

5) <script src="scripts/shop.js">
   → 声明 _allItems = [], _shopReady, _jxItems = []

╔═══════════════════════════════════════════════════════════════╗
║  Phase 2: DOMContentLoaded → loadAllData() (app.js L11-16)    ║
╚═══════════════════════════════════════════════════════════════╝

loadAllData() 三层优先级:

Step 1: localStorage 读取
  loadJSON("data/characters.json")
  → pathToKey → localStorage.getItem("crossing_characters_json")
  → 如果存在且含 characters → 直接使用，结束

Step 2: 扫描 dataBundle（仅在 Step 1 失败时）
  bundle = window._CROSSING_DATA || {}
  for key in bundle:
    if key starts with "data/characters/" && ends with ".json":
      提取 fileData.characters 中每个角色
      构建 availableChars[] = [{name, filePath, level, mainClass, race}]
  → 如果有角色 → showCharacterSelectDialog(availableChars)
  → 弹窗等待用户勾选 → confirmCharacterSelection() → characters[ch.name] = fileData[ch.name]
  → saveAllData() 写入 localStorage

Step 3: 无任何角色数据
  → showCreateGuide() → navigateTo('creation')

╔═══════════════════════════════════════════════════════════════╗
║  Phase 3: 页面导航 → 初始化 (navigateTo, app.js L28-49)       ║
╚═══════════════════════════════════════════════════════════════╝

navigateTo(page):
  1) 隐藏所有 .page → 显示 #{page}Page
  2) 更新 toolbar 按钮 .active 状态
  3) 非 main 页显示 toolbar (display:flex)
  4) creation 页隐藏所有导航按钮 .active
  5) 根据 page 调用对应初始化函数:
     character → initCharacterPage()
     shop      → initShopPage()
     dm        → renderDmOverview()
     jianxia   → loadJianxiaData()
  6) 设置 currentPage = page

╔═══════════════════════════════════════════════════════════════╗
║  Phase 4: 用户编辑 → 自动保存                                 ║
╚═══════════════════════════════════════════════════════════════╝

任意字段变更 → onCharFieldChange(key)
  → 更新 _mainXp / _mainAp（从 DOM 读取）
  → gatherCharData() → 从 DOM 收集完整 JSON
  → 如果 key === 'charName' 且名不同 → 原子改名
      delete characters[oldName]
      characters[newName] = gatherCharData()
      refreshCharSelector()
  → 否则 characters[currentCharName] = gatherCharData()
  → autoSave() → 500ms 防抖 → saveAllData()
      → saveJSON("characters.json", { characters })  // localStorage
      → [服务器模式] saveCharacterFile() → POST /api/data/characters/{name}.json

╔═══════════════════════════════════════════════════════════════╗
║  Phase 5: 商店购买                                            ║
╚═══════════════════════════════════════════════════════════════╝

用户点击购买 → buyShopItem(name)
  → 查找 _allItems 匹配项
  → 检查 property.mainXp >= item.xpCost && property.mainAp >= item.apCost
  → 扣除资源
  → 按类别路由:
      强化      → enhances[]
      武器/防具  → inventory[] + equipment (优先填空槽)
      心法      → activeSlots[]
      道具      → inventory[] (默认 0.5 重量)
  → autoSave() + refreshShop() + showToast()
```

### 2.3 运行模式

#### 模式 A：Electron 桌面应用 (推荐)

```bash
npm start
# Electron 启动 main.js → 创建 BrowserWindow → 加载 index.html
# 数据路径: dataBundle.js 内嵌 JSON → 无网络请求
# 持久化: localStorage (无服务器)
```

- `main.js` 为极简 Electron 壳 (21行)：创建 1360x860 窗口，加载 index.html，隐藏菜单栏
- **无 preload.js**，无 contextBridge，无 IPC
- `nodeIntegration: false`, `contextIsolation: true`
- 数据加载完全依赖 `dataBundle.js` + `localStorage`
- 无需运行 server.js

#### 模式 B：HTTP 服务器模式 (开发调试)

```bash
npm run server
# node server.js → http://localhost:3000
# 浏览器访问 → server.js 提供静态文件服务
```

- `isServerMode()` 检测 `window.location.protocol === 'http:' || 'https:'`
- 服务器模式下可调用 `saveCharacterFile()` 写入磁盘
- `deleteCharacterFile()` 可删除角色文件
- 服务器有目录穿越防护（path.normalize + 前缀白名单）

#### 模式 C：直接打开 HTML (需要 buildBundle)

```bash
npm run buildBundle
# → 生成 scripts/dataBundle.js
# 双击 index.html
```

- 纯 `file://` 协议，无服务器
- 全部数据来自 `window._CROSSING_DATA` 内嵌变量
- 写入仅到 localStorage（无法持久化到磁盘文件）
- 角色文件的 POST/DELETE 操作直接 resolve（静默跳过）

### 2.4 navigateTo 五页初始化代码 (app.js L28-49)

```js
function navigateTo(page) {
  document.querySelectorAll('.page').forEach(function(p) { p.classList.remove('active'); });
  var target = document.getElementById(page + 'Page');
  if (target) target.classList.add('active');

  document.querySelectorAll('[data-page]').forEach(function(btn) {
    btn.classList.toggle('active', btn.dataset.page === page);
  });

  var toolbar = document.getElementById('mainToolbar');
  if (toolbar) toolbar.style.display = (page === 'main') ? 'none' : 'flex';

  if (page === 'creation') {
    document.querySelectorAll('[data-page]').forEach(function(btn) {
      btn.classList.remove('active');
    });
  }

  currentPage = page;

  if (page === 'character') { try { if(typeof initCharacterPage==='function') initCharacterPage(); } catch(e){} }
  if (page === 'shop')      { try { if(typeof initShopPage==='function') initShopPage(); } catch(e){} }
  if (page === 'dm')        { try { if(typeof renderDmOverview==='function') renderDmOverview(); } catch(e){} }
  if (page === 'jianxia')   { try { if(typeof loadJianxiaData==='function') loadJianxiaData(); } catch(e){} }
}
```

**五页均已处理** — jianxia 路由在 v2.1 中已修复（旧版本缺失此判断，导致剑侠页面永久显示"加载中…"）。

## 4. 数据层 API (dataService.js v2.1)

### 4.1 常量

```js
var STORAGE_PREFIX = 'crossing_';
```

所有 localStorage key 以此为前缀。例如 `data/world_registry.json` → `crossing_world_registry_json`。

### 4.2 pathToKey(path)

```js
/**
 * 将文件路径转换为 localStorage key
 * @param {string} path - 如 "data/world_registry.json" 或 "/api/data/characters/李棠王.json"
 * @returns {string} - 如 "crossing_world_registry_json"
 */
function pathToKey(path) {
  var normalized = path.replace(/^data\//, '').replace(/^\/api\/data\//, '');
  return STORAGE_PREFIX + normalized.replace(/[^a-zA-Z0-9_-]/g, '_');
}
```

**映射表**:

| 输入 (path) | 输出 (localStorage key) |
|-------------|------------------------|
| `"data/world_registry.json"` | `"crossing_world_registry_json"` |
| `"/api/data/characters/丰川祥子.json"` | `"crossing_characters_丰川祥子_json"` |
| `"data/status_refs/bloodline.json"` | `"crossing_status_refs_bloodline_json"` |

### 4.3 loadJSON(path)

```js
/**
 * 读取 JSON 数据（异步）
 * 优先级：localStorage > 内嵌数据包 > 报错
 * @param {string} path
 * @returns {Promise<object>}
 */
function loadJSON(path) {
  var key = pathToKey(path);

  // 1) localStorage（用户修改过的持久化数据）
  try {
    var stored = localStorage.getItem(key);
    if (stored) return Promise.resolve(JSON.parse(stored));
  } catch (e) { /* ignore corrupt data */ }

  // 2) 内嵌数据包（种子数据，来自 dataBundle.js）
  var bundle = window._CROSSING_DATA || {};
  if (bundle[path]) return Promise.resolve(bundle[path]);

  // 3) 两处均无 → reject
  return Promise.reject(new Error('数据未找到: ' + path));
}
```

**关键行为**:
- localStorage 优先：用户编辑过的数据永远覆盖种子数据
- 不发起网络请求：所有数据来自内存（bundle）或 localStorage
- Promise 异步：即使数据是同步可得的，也包装为 Promise

### 4.4 saveJSON(path, data)

```js
/**
 * 写入 JSON 数据 → localStorage（异步）
 * @param {string} path
 * @param {object} data
 * @returns {Promise<void>}
 */
function saveJSON(path, data) {
  var key = pathToKey(path);
  try {
    localStorage.setItem(key, JSON.stringify(data));
    return Promise.resolve();
  } catch (e) {
    return Promise.reject(new Error('保存 ' + path + ' 失败: ' + e.message));
  }
}
```

**注意**: 此函数只写 localStorage，不写磁盘文件。服务器模式下的文件写入由 `saveCharacterFile()` 另外完成。

### 4.11 server.js API 详解

**文件**: `server.js` (118 行)

**启动**: `node server.js` → 端口 3000（可用 `PORT` 环境变量覆盖）

```js
const PORT = process.env.PORT || 3000;
```

**路由**:

| 方法 | 路径 | 功能 | 安全限制 |
|------|------|------|---------|
| GET | `/` | 返回 index.html | — |
| GET | `/*` | 静态文件服务 | `filePath.startsWith(__dirname)` 防止目录穿越 |
| OPTIONS | `*` | CORS 预检 | 返回 204 + CORS headers |
| POST | `/api/data/{path}` | 写入 JSON 文件 | 禁目录穿越 + 仅 .json |
| DELETE | `/api/data/{path}` | 删除 JSON 文件 | 禁目录穿越 + 仅 .json |

**POST 处理流程** (server.js L34-64):
1. 从 URL 提取相对路径 → `decodeURIComponent` → `path.normalize`
2. 去除 `../` 前缀（防目录穿越）
3. 拼接完整路径 → `path.join(DATA_DIR, safePath)`
4. 验证 `fullPath.startsWith(DATA_DIR)` → 不通过返回 403
5. 验证 `path.extname(fullPath) === '.json'` → 不通过返回 400
6. 接收请求体 → `JSON.parse(body)` 合法性检查
7. 确保目录存在 → `fs.mkdirSync(dir, { recursive: true })`
8. 写入 → `fs.writeFileSync(fullPath, body, 'utf-8')`

**CORS**: 所有响应包含 `Access-Control-Allow-Origin: *`，支持跨域开发。

### 7.2 负重计算

```js
// character.js updateLoadCalc() L333-351
function updateLoadCalc() {
  // 获取 STR 值
  var strVal = parseInt(document.getElementById('stat_str').value) || 10;

  // 获取承重熟练加值
  var carryProf = 0;
  if (_skillWidgets['athCarry'].check.checked && _skillWidgets['athCarry'].value) {
    carryProf = parseInt(_skillWidgets['athCarry'].value.value) || 0;
  }

  // 基础负重 = STR + 承重熟练值
  var base = strVal + carryProf;

  // 三级负重阈值
  document.getElementById('loadNormal').value = base * 5;   // 常规
  document.getElementById('loadMax').value = base * 10;      // 满载
  document.getElementById('loadLimit').value = base * 15;    // 极限

  // 当前负重 = Σ(物品重量 × 数量)
  var cur = 0;
  _inventory.forEach(function(i) { cur += (i.weight || 0) * (i.qty || 0); });
  document.getElementById('loadCurrent').value = cur;

  // 进度条 + 状态判定
  var pct = Math.min(100, (cur / (base * 15)) * 100);
  // 轻载 (≤ base*5): 绿色, 无惩罚
  // 中载 (≤ base*10): 橙色, 敏捷-2
  // 重载 (≤ base*15): 红色, 敏捷-5, 速度减半
  // 超载 (> base*15): 红色, 无法移动
}
```

**负重状态表**:

| 条件 | 状态 | 惩罚 | 进度条颜色 |
|------|------|------|-----------|
| `cur ≤ base×5` | 轻载 | 无 | `var(--accent-green)` |
| `cur ≤ base×10` | 中载 | 敏捷 -2 | `var(--accent-orange)` |
| `cur ≤ base×15` | 重载 | 敏捷 -5, 速度减半 | `var(--accent-red)` |
| `cur > base×15` | 超载 | 无法移动 | `#ff0000` |

**触发时机**: `onStatChange()` → STR 变化时 / `athCarry` 值变化时 / 物品重量变化时

### 10.2 file:// 协议限制

**问题**: 直接双击 index.html（`file://` 协议）时:
- `fetch()` 不可用 → CORS 错误
- server.js 的 POST/DELETE API 不可用 → 无法写入/删除磁盘文件
- 持久化仅能到 localStorage

**解决方案**: 
1. 先运行 `npm run buildBundle` 生成 dataBundle.js（绕过 fetch 加载数据）
2. 或使用 `npm run server` 启动 HTTP 服务器
3. 或使用 `npm start` 启动 Electron 桌面应用

### 10.3 无 preload.js

- `main.js` 仅 21 行，极简 Electron 壳
- `nodeIntegration: false`, `contextIsolation: true`
- **无 preload.js**，无 contextBridge，无 electronAPI
- 数据路径：`dataBundle.js` 内嵌 `window._CROSSING_DATA` → `dataService.js` 读取
- 与优化计划.md 中提议的完整 Electron IPC 方案完全不同

### 10.4 数据字段兼容性问题

| 问题 | 说明 | 当前处理 |
|------|------|---------|
| `xpMax` vs `xpNext` | 旧数据可能用 `xpNext`，代码读写用 `xpMax` | loadCharacterIntoUI 兼容两者；gatherCharData 同时写入两者 |
| `mainAp` 双路径 | `property.mainAp` 和 `wealth.achievePoints` 可能不同步 | loadCharacterIntoUI 优先 property → wealth；gatherCharData 两者都写 |
| `statusDetail` 缺失 | 旧角色数据可能无此字段 | loadCharacterIntoUI 自动创建默认值 (L448-456) |
| 货币模板 | createNewCharacter 创建 2 种，旧数据可能有 5 种 | loadCharacterIntoUI 从已有数据加载，不覆盖 |
| `characters.json` 单一文件 | 旧版使用单一文件，新版使用 12 个独立文件 | loadAllData 优先 loadJSON("data/characters.json") (从 localStorage)，其次扫描 bundle |

### 10.5 localStorage key 命名空间

所有 key 以 `crossing_` 为前缀（`STORAGE_PREFIX = 'crossing_'`）。路径规范化规则：
- `data/` 前缀被去除
- `/api/data/` 前缀被去除
- 非字母数字字符替换为 `_`
- 例如: `data/characters/丰川祥子.json` → `crossing_characters_丰川祥子_json`

### 10.6 角色切换

`onCharSelectorChange()` → `loadCharacterIntoUI(name, characters[name])` — 这是唯一将 JSON 映射到 DOM 的函数。切换角色时：
- `_inChange = true` — 锁定自动保存
- 依次回填所有 DOM 元素
- `_inChange = false` — 解锁

## 11. 自动更新系统

**版本**: v2.2 新增  
**依赖**: `electron-updater ^6.0.1` + `electron-log ^5.3.0`

### 11.1 架构

```
┌──────────────────────────────────────────────┐
│  Renderer (index.html + app.js)              │
│  window.electronAPI.checkForUpdates()        │
│  window.electronAPI.onUpdateStatus(cb)       │
└───────────────┬──────────────────────────────┘
                │ contextBridge (preload.js)
┌───────────────▼──────────────────────────────┐
│  Main Process (main.js)                      │
│  ipcMain.on('check-for-updates', ...)        │
│  autoUpdater.checkForUpdates()               │
└───────────────┬──────────────────────────────┘
                │ GitHub API
┌───────────────▼──────────────────────────────┐
│  GitHub Releases                             │
│  Konkilino/crossingTRPG                      │
│  latest.yml → 版本比较 → NSIS 安装包下载      │
└──────────────────────────────────────────────┘
```

### 11.2 文件清单

| 文件 | 用途 |
|------|------|
| `preload.js` | contextBridge IPC 桥接，暴露 `window.electronAPI` |
| `main.js` (更新后 ~110 行) | autoUpdater 配置、IPC 处理器、事件转发 |
| `dev-app-update.yml` | 本地开发测试配置（不打包进生产） |
| `package.json` → `build.publish` | GitHub provider 配置 |

### 11.3 preload.js API

**文件**: `preload.js`

```js
window.electronAPI = {
  // 触发检查更新
  checkForUpdates: () => ipcRenderer.send('check-for-updates'),
  // 开始下载
  startDownload: () => ipcRenderer.send('start-download'),
  // 退出并安装
  quitAndInstall: () => ipcRenderer.send('quit-and-install'),
  // 获取当前版本（Promise → string）
  getVersion: () => ipcRenderer.invoke('get-app-version'),
  // 监听状态变化 (status, data) → cleanup()
  onUpdateStatus: (callback) => { ... },
  // 监听下载进度 { percent, transferred, total } → cleanup()
  onDownloadProgress: (callback) => { ... },
};
```

**安全规则**: 绝不直接暴露 `ipcRenderer`，每个方法单独包装（Electron 29+ 安全要求）。

### 11.4 更新流程状态机

```
启动 (isPackaged=true, 3s后)
  │
  ▼
[checking] ──→ 已是最新 → [not-available] (3s后自动消失)
  │
  ▼
[available] ← 用户点击"下载更新"
  │
  ▼
[download-progress] — 重复触发，percent 递增
  │
  ▼
[downloaded] ← 用户点击"立即重启"
  │
  ▼
quitAndInstall() → 关闭应用 → NSIS 安装新版本 → 重新启动
```

**错误状态**: `[error]` — 任意节点失败时触发，8s 后自动消失。

// main.js
